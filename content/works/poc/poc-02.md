## Overview

발명의 요지·핵심 기술 포인트·선행 기술 맥락을 입력하면, 특허 명세서 초안의 표준 구성(발명의 명칭, 기술분야, 배경기술, 발명의 내용, 실시예 등)에 맞춰 문단 구조와 초안 문장을 생성하는 PoC입니다. 변리사 검토 전 1차 초안 작성 시간을 줄이고, 항목별 누락을 방지하는 것을 목표로 설계했습니다.

## Problem

- 특허 명세서 초안은 형식·항목이 정해져 있어, 발명자·기획자가 처음부터 전체 구조를 채우기 어렵습니다.
- 기술 포인트만 정리된 상태에서는 배경기술·발명의 효과·실시예 간 논리 연결이 약해지고, 초안 품질 편차가 큽니다.
- 반복되는 서술·누락 항목을 사람이 일일이 점검하는 데 시간이 많이 듭니다.

## Role & Scope

- 명세서 섹션 정의, 입력 폼·생성 파이프라인 설계, 프롬프트·출력 스키마 구성, 데모 UI까지 PoC 전 과정을 담당했습니다.
- PoC 범위: 텍스트 입력 기반 초안 생성, 국내 특허 명세 스타일 가이드 반영, 섹션별 개별 재생성.
- 실제 출원·선행조사 자동화·법률 자문·다국어 명세 전문 번역은 범위에서 제외했습니다.

## Approach

- 발명 요지·기술 포인트·(선택) 선행 기술 요약을 받아, 명세서 목차별 생성 순서를 고정해 누락을 줄였습니다.
- 섹션마다 프롬프트·출력 JSON 스키마를 분리해, 배경기술·발명의 내용·실시예가 서로 모순되지 않도록 단계적으로 생성합니다.
- 생성 결과에 체크리스트(필수 항목·권장 분량)를 함께 제공해, 사용자가 수정·보완할 지점을 빠르게 파악할 수 있게 했습니다.
- 동일 발명에 대해 섹션 단위 재생성을 지원해, 전체를 다시 쓰지 않고도 부분 수정이 가능합니다.

## Tech Stack

- LLM API · 프롬프트 체인(섹션별 초안 생성 / 정합성 보완)
- Python · FastAPI — 입력 검증, 생성 Job·버전 관리
- React — 입력·초안 미리보기·섹션 편집 UI(데모)
- 명세서 섹션 JSON 스키마 · 구조화 출력 파싱

## Outcome

- 발명 요지 입력 후 주요 섹션 초안을 엔드투엔드로 생성·확인하는 데모를 완료했습니다.
- 섹션별 체크리스트로 누락 항목을 줄이고, 초안 수정 라운드를 1~2회로 압축할 수 있음을 내부 검증했습니다.
- 프롬프트·섹션 가이드 문구를 템플릿화해, 유사 발명 유형에 재사용 가능한 기준을 정리했습니다.
- 후속: 선행문헌 요약 연동, 청구항 초안 생성, 변리사 협업용 diff·주석, 영문 명세 초안.
